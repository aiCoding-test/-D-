# 07 验收与实施计划

> 本文为设计阶段基线；实际实现与验证结果请参阅 [实现差异](09-实现差异与限制.md) 和 [验收记录](../evidence/acceptance.md)。

## 1. 验收原则

核心证据应来自真实状态、真实进程故障和产物校验。把一个 Step 的 status 手工改成 FAILED 只能演示 UI，不能证明进程中断恢复。

每次验证记录：环境与版本、输入和故障方案、操作步骤、Task/Step/Attempt ID、期望状态、实际事件、产物指纹、耗时及结论。尚未执行的用例标“未验证”，不能写成“通过”。

业务计算可 MOCK；事务、状态机、领取竞争、租约过期、重启、缓存校验和文件提交应真实运行。所有数据库锁和并发验证使用 PostgreSQL。

矩阵中的场景可以由少量参数化集成用例和可复现人工演示覆盖，不要求建设独立测试平台，也不要求每行都另写一个测试文件。优先自动验证所有权、持久化与完整性不变量。

## 2. P0 验收矩阵

| ID | 场景与故障注入 | 期望行为 | 必需证据 |
| --- | --- | --- | --- |
| A01 | 正常完成 7 步 | 父依赖先成功；图集/预览可并行；二者完成才打包 | DAG、事件顺序、最终 manifest |
| A02 | 相同幂等键并发提交相同请求 | 只创建一个 Task，返回同一 ID | 两响应与唯一任务记录 |
| A03 | 同幂等键提交不同参数 | 409，原 Task 不变 | 请求指纹和响应 |
| A04 | 抠图首次注入瞬时失败 | Attempt1 FAILED，退避后 Attempt2 成功；抽帧不重跑 | 两次 Attempt、next_run_at、上游尝试数 |
| A05 | 抠图始终失败，耗尽预算 | 最多 3 次尝试；下游 BLOCKED；任务收敛为 FAILED | 次数、错误链、阻塞原因 |
| A06 | 永久输入错误或模拟稳定 OOM | 不做无效自动重试；提供明确错误 | Attempt 次数与错误策略 |
| A07 | 抠图中终止整个 Worker 容器并重启 | API 仍可查询；租约过期，旧 Attempt LOST；安全清理后新 Attempt 接续 | 真实 kill/restart 操作、事件、产物卷保留 |
| A08 | 旧 Attempt 被接管后发回成功 | 旧提交、续租和进度均拒绝；新结果保持 | 两 token、冲突响应、正式产物指纹 |
| A09 | 领取提交后、子进程开始前中断 | 启动窗口不丢任务，最终超时/失联并重试 | STARTING Attempt 与恢复记录 |
| A10 | 临时文件写到一半时杀执行器 | 下游不读半文件；重试产物独立 | 工作目录、正式引用与校验 |
| A11 | 文件已发布、DB 成功前注入中断 | 没有成功状态或缓存误命中；可能产生孤立文件并重算 | 文件、DB 引用、后续 Attempt |
| A12 | DB 成功后、Worker 收到确认前中断 | 重读成功结果，不重复推进或覆盖 | 幂等完成、单份正式引用 |
| A13 | 预览编码失败，GPU 步骤已完成，人工恢复 | 新 epoch；GPU 成功结果保留，仅未完成部分新增尝试 | 前后 epoch、各 Step Attempt 数 |
| A14 | 相同素材/参数新建另一 Task | 有效步骤 CACHED，无计算 Attempt；缓存来源可追溯 | 两 Task、缓存引用、命中统计 |
| A15 | 只改预览编码参数 | 预览与打包重算，其他适用步骤复用 | 各 Step 键、命中/重算记录 |
| A16 | 改模型权重、种子或 simulated 模式 | 受影响步骤缓存身份变化，不误用 | 缓存键差异及来源 |
| A17 | 删除或损坏已有缓存文件 | 拒绝命中，标无效；重新执行或给完整性错误 | checksum、失效事件、新产物 |
| A18 | 两个任务争抢一个模拟 GPU | 同一时刻至多一个持有者；另一 Step READY；等待不消耗 Attempt | 槽位历史、排队原因、Attempt 数 |
| A19 | 租约过期但旧执行器仍存活 | 槽 QUARANTINED，不能直接复用；授权写入拒绝 | 活进程证据、隔离记录、清理确认 |
| A20 | 子进程挂起但 Supervisor 正常 | 心跳持续、进度停滞可见；运行超时生成 TIMED_OUT | 心跳、last_progress_at、超时事件 |
| A21 | 取消与最后成功同时发生 | 按任务锁顺序胜出：成功先提交则取消 409；取消先提交则完成拒绝 | 两种受控竞争记录 |
| A22 | DB 短暂不可用 | 停止领取；不能续约则停止/隔离本地工作；恢复后重验授权 | DB 中断记录、无越权成功 |
| A23 | Worker 在退避期重启 | 不清零次数、不提前重试、不重算退避计划 | next_run_at 与尝试计数 |
| A24 | API 重启、浏览器断线再刷新 | Worker 继续；快照与时间线恢复，不依赖浏览器内存 | 重启前后相同任务与事件 |
| A25 | 两 Worker 并发领取同一 Step | 唯一当前 Attempt；不能双分配同一槽 | 争抢记录和约束结果 |
| A26 | 并发事件提交与增量查询 | 每任务 seq 不漏不倒退；快照游标与内容一致 | 事件集合、快照与重复去重 |
| A27 | 失败后输出被损坏，再人工恢复 | 失效根及后代重新执行，其余有效分支可保留 | 失效事件、重跑范围、历史不丢 |
| A28 | 查询未知 ID、重复取消/恢复、非法版本/参数 | 返回稳定 4xx；命令重发不会再次增加 epoch | 响应与 command receipt |

A08 可以用受控完成回报构造迟到消息；A07/A19 必须包含真实进程生命周期证据。A11/A12 需要在发布/事务边界设置确定性故障点，避免只靠随机杀进程碰运气。

建议提供以下预置故障方案，避免验收依赖临时手改状态或业务参数：

| 方案 | 固定行为 | 主要用途 |
| --- | --- | --- |
| `normal` | 全部计算正常 | DAG 与基本产物 |
| `transient_once` | 抠图在当前代次 Attempt1 失败，其余正常 | 自动退避与上游结果保留 |
| `resume_preview` | 第 1 代次预览的 3 次尝试均瞬时失败，第 2 代次正常 | 人工恢复；无需更改任务输入 |
| `gpu_oom` | 抠图返回稳定 OOM | 不盲目原配置重试 |
| `slow_step` | 指定 MOCK 步骤持续较长并上报进度 | 心跳、取消、超时与杀容器 |

这些控制字段进入提交请求指纹以保证幂等，但不进入计算语义缓存键。故障演示默认使用独立演示素材指纹或关闭缓存读取，否则已有缓存可能跳过预定故障；缓存验收场景再显式启用。关闭缓存读取只影响执行策略，不改变产物语义。事务边界故障点只在本地测试模式开放。

## 3. 分层验证方式

- **领域验证**：DAG 校验、允许状态转换、错误分类、退避边界、缓存指纹的语义差异。聚焦不变量，不为简单 getter 写测试。
- **数据库集成验证**：并发领取、锁顺序、CAS、唯一约束、幂等提交、事件顺序与命令收据。
- **真实进程验证**：终止 Worker 容器、终止/挂起执行器、数据库断连、恢复后产物与尝试计数。
- **接口与页面核对**：页面展示状态与 API 一致，模拟标记可见，刷新后历史仍在，非法操作有明确错误。

先完成有意义的恢复闭环测试，再扩充页面细节。最终回归以“这些不变量是否被破坏”为标准，不用测试数量代替质量。

## 4. P1 与长跑验证

| 场景 | 证据与限制 |
| --- | --- |
| MOCK 帧块检查点，完成两块后中断 | 只补剩余块；校验块 manifest；声明不证明真实模型检查点 |
| 小时级 MOCK 长跑中断恢复 | 心跳稳定、API 可查、资源不泄漏、重试与超时正常；记录真实持续时间 |
| 真 GPU OOM / 设备绑定 / 采样 | 驱动、型号、UUID、运行日志和 NVML 采样；无硬件时标未验证 |
| 真模型步骤恢复 | 把整步重做、帧块恢复和模型内部恢复分开写结论 |

## 5. 时间规划：20 小时预算基线

这是待确认的单人开发预算示例，按已有 Python 与 Docker 基础估计，不是已发生耗时，也不是完成保证。核心正确性超出预算时优先缩减 P1 和页面复杂度。

| 阶段 | 预算 | 主要输出 | 离开阶段的条件 |
| --- | --- | --- | --- |
| 1 场景与设计收敛 | 1.5h | DAG、状态、恢复与验收定义 | 明确 MVP 和不保证的边界 |
| 2 数据库与接收闭环 | 2h | 迁移、幂等提交、最小查询 | 重启可查，同键不重复 |
| 3 单步 Worker 与产物协议 | 3h | 领取、监督、心跳、不可变文件、完成事务 | 一步运行与成功提交可追踪 |
| 4 恢复与控制 | 3h | LOST、退避、fence、取消、人工恢复 | 杀 Worker/迟到回报/超时通过 |
| 5 完整 DAG 与缓存 | 2h | 7 步 MOCK、分支、版本缓存 | 失败保留上游与缓存失效通过 |
| 6 模拟资源与观测 | 1.5h | 槽位排队、隔离、模拟采样 | 并发/失联不会误分配 |
| 7 页面与接口补齐 | 2h | 列表、DAG、尝试时间线、资源区 | 刷新后能解释任务全过程 |
| 8 故障回归与复现 | 3h | 核心验收、演示数据、问题修复 | 必需不变量有运行证据 |
| 9 交付整理 | 1h | README、说明、实际过程记录、公开仓库检查 | 全新环境可启动，结论诚实 |
| 10 机动 | 1h | 兼容与复现问题 | 不以未验证功能充数 |
| **总计** | **20h** | **P0 为目标，P1 单独预算** | **若超时，记录原因并调整范围** |

建议在阶段 3 后立刻演示单步闭环，阶段 4 后优先验证杀进程恢复，再继续扩展。恢复模块是最大不确定项，不能等到最后才测试。

真实 GPU 接入、小时级长跑和分块检查点需要额外预算。长跑有自然墙钟成本，不能用 3 小时故障回归预算暗中包含多小时模型实验。

## 6. 开发过程的记录方式

每次工作记录阶段、开始/结束、本人主动操作时间、LLM 等待时间、工具与模型、可获得的 token 用量、主要修改及验证结果。个人时间统计排除 LLM 自动生成和等待时长，避免把整个聊天时长等同本人投入。

token 使用实际工具/会话统计，注明输入、输出、缓存 token 的口径。无法取得精确数据就写“不可得”，若估算则注明方法与误差。不能把字符数直接当准确 token，也不能预先编一个总量。

## 7. 推荐演示脚本：5～8 分钟

1. 提交正常任务，展示固定 DAG、两个 CPU 分支与最终 MOCK manifest，明确计算是模拟的。
2. 提交首次抠图失败场景，展示 Attempt1 错误与 Attempt2 成功，上游尝试数不变。
3. 执行过程中杀 Worker 容器，保持 API 查询；重启后展示 LOST 和新 Attempt，成功步骤保留。
4. 新建相同输入任务展示缓存命中，再展示预览参数变化只影响相应后代。
5. 两任务竞争模拟 GPU，展示排队、占用者与遥测来源；补充失联隔离结果。
6. 打开失败时间线和限制说明，说明小时级、真 GPU 与分块恢复的已完成/未完成边界。

短演示可用 5 秒心跳、15 秒租约加速等待，但必须标明演示参数；不能为了演示把生产恢复保证写得更强。完整验收仍按明确配置记录。

## 8. 项目完成标准

- 已实现功能与本设计范围一致，偏差记录在交付说明；P1 未实现清楚列出。
- A01～A28 有实际执行结果；若存在未通过或未验证项，说明影响，不写“全部通过”。
- 至少提供正常执行、瞬时失败、Worker 中断、缓存复用/失效、模拟 GPU 排队五组证据。
- 公开 GitHub 仓库可匿名读取，包含源码、锁依赖、示例配置、启动方式及验收记录；若选择公网交付，URL 可实际访问。
- 从全新环境启动验证成功，持久卷要求和停止/重启方式明确。
- 题目要求的 AI 工具、token、个人耗时和失败分析以真实记录填写。
