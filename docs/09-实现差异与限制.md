# 实现与原设计的差异

docs/01～07 保留为设计基线。本文件说明最终 P0 的简化和限制，实际结果见 [验收记录](../evidence/acceptance.md)。

| 设计项 | 最终实现 | 原因与影响 |
| --- | --- | --- |
| 领域/仓储多级目录 | models、pipeline、service、worker、artifacts、queries、api 小模块 | 固定 DAG 无需多层抽象；关键事务集中在 service |
| 独立依赖表 | Task 流程快照与 Step 的冻结 deps | 创建前校验，无动态改图，依赖仍可查询 |
| 通用产物集合 | 每步一个集合，真实 JSON/SVG MOCK 文件与 manifest | 聚焦控制协议；最终打包为模拟结果集合 |
| PID 辅助回收 | 子进程继承共享卷的 Linux flock | 不依赖跨容器 PID 猜测停止；要求共享卷支持正确文件锁语义 |
| 协调循环续租 | 协调续租 + 不访问 DB 的独立看门狗 | 实际停库发现 DNS 等待可阻塞；看门狗及时停止本地计算 |
| 资源历史采样表 | 槽位保存最新模拟样本，Attempt/事件保留占用历史 | 满足 P0 查询；没有长期利用率曲线和时序监控平台 |
| 取消中间态 | 事务撤销授权、槽位隔离后即可收敛 CANCELLED | 物理清理稍后完成，cleanup_state 和 QUARANTINED 仍可查询，任务终态不代表内核即时停止 |
| 等待原因 | Step 显示 CPU_BUSY/GPU_BUSY，资源卡片显示隔离原因 | 隔离原因以资源查询为准；没有增加复杂调度状态 |
| 聚合监控 | 状态计数、尝试总数、缓存步骤数和各尝试时刻 | 耗时字段可查询；未实现设计中的全部聚合统计或外部监控导出 |
| 完整历史页面 | API 按每任务 seq 分页；详情展示最近 100 条事件 | 历史仍持久保存，页面尚无历史翻页与筛选控件 |
| 日志 | 业务事件 JSON 日志、HTTP/Worker 运行日志，错误进 DB | 普通日志不承担事务和恢复职责，无独立日志检索系统 |
| 任意素材输入 | 两个自有 SVG 动画样例，服务端计算内容哈希 | 不扩展上传、远端抓取与不可信代码执行 |

## 恢复和存储边界

数据库保存任务、步骤、尝试、输入与 DAG 快照、重试时间、租约/fence、事件、控制命令收据、缓存索引、产物摘要、Worker 会话和资源占用；实际文件保存在 Docker named volume，API 只读挂载。

行锁只覆盖短事务，完成后不依赖内存回调；扫描根据持久状态继续推进。人工恢复增加 epoch，重设本代次截止和重试预算，保留有效成功结果与全部旧尝试。

文件先发布、后提交引用，故障窗口可能重复计算并留下孤立文件。P0 没有自动 GC，不能无限运行直到磁盘耗尽。Linux flock 只证明可信执行器的存活边界，不支持绕过协议的处理器或文件锁语义不可靠的存储。

文件系统与 DB 不存在分布式原子事务，人为在校验后删除文件仍可使已提交产物不可用；消费/下载会再次校验并报错。恢复失败任务时显式重算无效祖先及后代，已成功 Task 不会被后台改写。

未验证：宿主掉电、磁盘损坏、数据库永久丢失、小时级模型运行、真实 GPU/NVML、多租户隔离和跨机调度。默认仅在本机开放服务，公开交付为源码仓库。

## 小时级演进

保持短租约，提高业务超时，为昂贵帧处理增加带产物哈希的分块检查点。大文件需要流式 IO、独立校验/提交路径、存储容量与日志保留预算。真实 GPU 另接设备绑定和 NVML，不能复用 MOCK 指标或缓存。sleep 一小时不能证明真实模型/GPU 稳定性。
