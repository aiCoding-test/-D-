# P1：分块恢复和长任务观测

本次只实现不依赖真实 GPU 的 Goal A。真实 GPU/NVML、SSE、公网服务和分布式调度没有加入范围。

## 版本和兼容

新任务默认 `animation-v2`，抠图/增强使用 `mock-chunks-1`，96 帧按 `frames-24-v1` 拆为 4 块。`animation-v1` 与原处理器继续保留，旧任务按冻结快照执行，旧产物和尝试不改写。

Alembic 新增 `0002`：Checkpoint、CheckpointUse、ResourceSample，以及 Attempt.queue_seconds。已发布的 `0001` 文件未修改。旧记录没有排队测量时返回 null，不补造数字。[旧数据升级证据](../evidence/p1-upgrade.json)

## 检查点协议

子进程只写本 Attempt 私有块目录和就绪标记，不接触数据库。Worker 校验块文件、发布到不可变目录，再在当前 Task/Step/Attempt、epoch、租约及 fence 授权下提交检查点。确认提交后写 ack，子进程才推进下一块。

块身份包含完整步骤语义指纹、输入摘要、模型/处理器版本、有效参数、分块版本和帧区间。Checkpoint 是不可变产物与来源记录，CheckpointUse 记录某次尝试使用了哪个块、是否复用；已失效块保留历史。

块 schema 1 固定为仅含一个 `output.json`，JSON 为 `{simulated: true, chunk_identity: <完整冻结身份>}`。登记、恢复和汇总均校验 schema、身份与文件哈希；即使文件哈希自洽，只有进度或 frame_index 的 JSON 也不能作为检查点。

重试和人工恢复会逐块验证，只补坏块和缺失块。旧 Attempt 的迟到块、进度和最终汇总均被拒绝。汇总前要求本 Attempt 有全部有效块的使用记录；完整输出复制块文件并独立校验，下游只消费完整 Step 产物。

同一个 Step 的块可以跨 Attempt/epoch 复用；跨 Task 仍走完整 Step 缓存。整步 CACHED 不伪造块计算或 Attempt，页面明确区分两种复用。

文件发布但事务尚未提交时仍可能留下孤立文件；不会按文件存在自动认领。无自动文件 GC，检查点与正式产物均保留，不因原 Attempt 结束删除。

## 小时级配置

`execution_profile=hourly` 是显式选择：两个分块步骤分别配置 1800 秒，单块 450 秒，普通步骤约 0.2 秒，关闭完整 Step 缓存读取；Step 超时 2700 秒、Task 截止预算 9000 秒。默认 demo 不变。心跳仍为 5 秒、租约 30 秒。

```powershell
# 已有 Python 3.12、httpx 和 Docker 权限；后台执行并保留日志
Start-Process -FilePath '.venv\Scripts\python.exe' -ArgumentList @('-u','scripts\verify_hourly.py') -WorkingDirectory (Get-Location).Path -RedirectStandardOutput 'runtime\hourly.out.log' -RedirectStandardError 'runtime\hourly.err.log' -WindowStyle Hidden
```

Linux/macOS 可用 `.venv/bin/python -u scripts/verify_hourly.py > runtime/hourly.log 2>&1 &`。

辅助脚本使用独立 `taskd-hour` 项目、18081/55434 端口与 10.233.86.0/24 网络，数据库/文件卷不与普通演示共享。两块提交后实际 SIGKILL Worker 容器，接续只补后两块。进程与观察记录见 [hourly.json](../evidence/hourly.json)、[观测记录](../evidence/hourly-observations.jsonl)。

脚本拒绝覆盖已有证据。观察器意外退出时，先核对 PID/创建时刻和实际任务状态，再用 `--resume` 重新观察同一个任务；不会新建任务、清零开始时刻或重启计算。短暂 API 断开会记录观测缺口并重连。

只有实际持续至少 3600 秒、任务成功、旧块保留、成功块没有重复提交、资源回收均有证据，才算长跑通过。它证明 MOCK 控制协议与分块恢复，不证明真实模型/GPU 性能或内部检查点。

运行中执行 `python scripts/audit_hourly.py --observe` 会短暂向当前计算子进程发送 SIGSTOP，并在 finally 中 SIGCONT；验证业务进度暂停时控制进程仍续心跳/租约。普通运行时两者可在同一次事务更新时间，因此不能靠“时间戳必须不同”判断分离。长跑成功后运行 `python scripts/audit_hourly.py`，独立核对数据库起止、下载哈希、事件、资源回收及 Docker 进程事件。

全新克隆启动复现：先匿名 `git -c credential.helper= clone` 到未使用目录，再执行 `python scripts/verify_clean.py <克隆目录>`。脚本拒绝复用同名卷；重复验收可显式指定新的 `--project --api-port --db-port --subnet`，不删除旧卷。测试包含自动迁移、v1/v2 执行、全部文件下载校验与 API/Worker 重启持久化。

## 可观测接口和保留期

| 接口 | 用途 |
| --- | --- |
| `GET /api/tasks/{id}` | 当前块、已提交块数、复用数、帧区间及来源 Attempt |
| `GET /api/tasks/{id}/events?before_seq=&step_key=&attempt_id=&limit=` | 向前翻历史及筛选；保留 after_seq 增量语义，不能混用前后游标 |
| `GET /api/tasks/{id}/timings` | READY 到领取排队、Attempt 运行、LOST 检测和接管开始延迟 |
| `GET /api/resources/history?slot_id=&since=&until=&cursor=&limit=` | 资源原始/汇总样本、有效性、执行归属、保留策略；保留期导致游标失效返回 410 |
| `GET /metrics` | Prometheus 0.0.4 文本格式，固定状态/资源类型等低基数标签 |

Worker 默认最多每 5 秒为每槽持久化一个原始样本。原始保留 1 小时，之后按完整分钟汇总，分钟记录保留 7 天；维护循环每 60 秒运行、每批最多 10000 行。无 Worker 时不执行清理，重启后继续维护。

汇总只对有效数值求均值，整段无有效样本仍是 unavailable；保留 valid_count/sample_count 和 holder_ids，不能用空样本填 0。维护只操作资源样本，不删除 Task、事件、检查点或执行历史。

指标以持久记录计算：重试额外尝试数、检查点提交/复用累计数；当前状态/整步缓存数为 gauge；耗时 sum/count 是有定义范围的聚合 gauge。无 task_id、attempt_id 等高基数标签。设备级模拟利用率不等于业务进度。

格式依据 [Prometheus 官方 exposition 文档](https://prometheus.io/docs/instrumenting/exposition_formats/)。

## 验证与已知问题

- P0 测试显式请求冻结 `animation-v1`，保留原正确性断言；新增 P1 用例验证 v2，不把版本变更混进旧断言。
- 新用例包含两块后真实杀进程、半块、提交前/后崩溃、重复 ack、迟到写入、取消竞争、坏块恢复、语义身份、超过 100 条事件分页和资源保留。
- 浏览器使用真实失败任务加 5 次合法人工恢复生成 128 条历史，实际点击翻页加载完毕；没有手改任务状态。
- 更新长跑 API 时一次遗漏专用网段配置，导致 API 短暂关闭，计算 Worker 未重启；旧观察器没有处理连接中断而退出。修复为固定网络覆盖及可重连/同任务重附着，保留了观测间断记录，没有重新提交任务。
- 资源历史、检查点和业务事件均为单机小规模实现，不承诺时序数据库吞吐、训练恢复或高可用集群。

实际完成状态以 [P1 验收记录](../evidence/p1-acceptance.md) 为准；长跑未结束时不能用快测通过替代完整 P1 验收。
